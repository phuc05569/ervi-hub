# Ervi Hub 3.4 interface redesign (14 Nov 2026)

This is UI/UX and settings-persistence work on top of the 3.3 development integration, which was committed first and separately. Gameplay, combat, movement, targeting, networking, ESP detection/visibility logic and loader/security code are unchanged. It is a development-branch build, not a release.

## Files

- **Changed:** `src/App.luau`, `Ui.luau`, `Theme.luau`, `Motion.luau`, `Logo.luau`, `Settings.luau`, `SliderValue.luau`.
- **Small edits:**
  - `FeatureSchema.luau`: skeletonThickness range and description.
  - `Expansion.luau`: thickness readout.
  - `Visuals.luau` / `VisualPreview.luau`: stroke presentation only.
  - `build.py`: module list and version 3.4.0.
- **New:** `src/UiAssets.luau` (generated by `assets/ui/generate.mjs`), `src/UiImages.luau`, `src/SkeletonStroke.luau`, `assets/ui/*` (PNGs, SVG, generator, Lucide ISC license), `tests/UiPolish.spec.luau`, `reports/evidence/ui-3.4/*`.
- **Tests:** `tests/run.luau`, `tests/smoke/driver.luau`, and `tests/smoke/MockEngine.luau` (write counter, ContentProvider preload mock).
- **Docs:** AGENTS, README, CHANGELOG, HANDOFF, UI checklist.

## What changed

- **Visual system:** a liquid-glass approximation.
  - `Ui.glass` adds specular gradient rims, re-themed on every look change; `Ui.sheen` adds soft luminance gradients. Radii are 16/14/12/8 px.
  - Glass is applied to the window, content panel, cards, nav pill, title buttons, search, dropdowns, notifications, tooltips and the profile card.
  - There is no backdrop blur: Roblox UI has none, and the existing optional Background Blur setting is unchanged.
- **Logo:** an antialiased PNG rendered from the exact `LogoGeometry` polygons. Against the official reference it has an identical 130×138 bounding box and aspect ratio, with IoU 0.92 at 1:1 (the loss is in antialiased edge pixels).
- **Icons:** a Lucide (ISC) atlas with 18 distinct glyphs, one ImageLabel per icon. Each section has its own glyph: dices, layers, house, swords, eye, user, globe, shield, map pin, wrench, gear, activity, server; unknown sections get a dot. The native fallback also uses a distinct shape for every section.
- **Navigation:** a single glass pill glides behind the selected item (220 ms Quint), with hover, press and selection tints, and an 8–10 px page slide-in.
- **Motion:** named easings (out/soft/spring/accelerate) on the existing Motion owner, so interruption, reduced-motion and speed behavior are unchanged.
  - Open is 240 ms from 96% scale; close is 160 ms accelerate.
  - The toggle knob uses a spring; notifications slide in and out.
- **Config page removed:** the slot list, Save as, Overwrite, Load, autoload, import/export and sharing controls are gone. `Settings.export/import` remain as data-only module functions.
- **Autosave:** every `savePrefs()` call is debounced (350 ms) into a single write. Pending writes are flushed on unload and on teleport. The sidebar shows the status: "Saved automatically", "Saving…", "Save failed", or "Session only" when the executor has no file API.
- **Profile migration:** the profile that was already effective stays active (per-game autoload, then global autoload, then Default; the owner's file resolves to `DEFAULT`).
  - The file format is unchanged and other named profiles are kept.
  - `RNG_Hub_settings.pre-autosave-backup.txt` is written once, before the first 3.4 write, and never overwritten.
- **Sliders:** the readout is an editable numeric field. Percent sliders take the number as shown, so typing 55 means 55%. Values are rounded to remove float noise (0.3 stays exactly 0.3).

## Image packaging and fallback

- The PNGs are **embedded in the bundle** as base64 (`UiAssets`, about 29 KB of source), so a bundle loaded from GitHub or from a local file carries them. Nothing is read from the developer's disk or downloaded.
- At start, `UiImages` writes `Ervi_Hub_ui-logo-<ver>.png` and `Ervi_Hub_ui-icons-<ver>.png` to the root of the executor workspace (no folder API needed). Both are rewritten every start, so a damaged file heals itself.
- It then calls `getcustomasset` and uses the image only if `ContentProvider:PreloadAsync` reports `Success`, waiting up to about 3 s.
- Any missing API, error or failed load leaves the native scanline logo and the native icons in place.
- **Engine check (Studio):** `PreloadAsync` returned Success for the real logo in 37 ms, and Failure for a missing file and for a corrupt file.
- **Smoke checks:** the PNG signatures are written by the bundle itself; verified images are used; a failed load falls back to native; an erroring `getcustomasset` falls back to native; no resources leak.
- Not yet run inside Potassium (deployment was not authorized).

## Fractional thickness: renderer finding

Studio probe (`evidence/ui-3.4/probe-fractional-widths-raw-frames.png`): GUI Frames **thinner than 1 px are not drawn**, and 1.5 px draws the same as 1 px. The 3.3 minimum of 0.5 px therefore made the skeleton invisible. `SkeletonStroke.resolve` now draws:

- **Below 1 px:** a 1 px white core with opacity equal to the thickness, and a black outline that fades with it.
- **1 px and up:** the width rounds to whole pixels, and the readout says so (for example "1.4 px · draws 1").

## Bugs found and fixed during 3.4 work

1. Skeleton thickness below 1 px rendered nothing (3.3 allowed 0.5).
2. Typing "50" into a percentage readout set 150%.
3. Float noise in slider values (0.30000000000000004).
4. The header description was clipped; the search placeholder and "no file access" status were truncated.
5. Images that `getcustomasset` returned but the engine could not load would have shown as blank; they now fall back to native.

## Verification (actual)

- Unit: 173 passed. Smoke: 545 passed, 0 failed. Release and loader compile; two consecutive builds are byte-identical; `git diff --check` is clean.
- The 3.3 commit was rebuilt and tested on its own (167 unit / 543 smoke; bundle `3.3.0+b241d2cece08`, identical to the paused build).
- **Studio** (`ErviUITest.rbxlx`, 810×675, unpublished, not saved):
  - Home, Settings, Visuals, Player, minimized pill and native fallback captures are in `reports/evidence/ui-3.4/`.
  - Six rapid toggle-key presses settle to visible, scale 0.85, same position.
  - Unloading during the open animation removes all GUIs with a clean stop and no errors.
  - UI scale 50/75/85/100/150% keeps the window center at (405, 308.5); above about 90% it is capped to fit the viewport.
  - The skeleton preview at 0.3 px and 3 px is visibly different.
  - Studio has no `getcustomasset`; it was emulated with temporary `rbxasset` copies, which were removed afterwards.

## Not verified / limitations

- The image path has not run in Potassium itself; if it fails, the hub falls back to native automatically.
- Persistence across real restarts is verified only in the mock file system; Studio has no file API.
- No 1920×1200 or 1280×720 capture, because the Studio window is 810×675.
- The live ESP renderer was not re-profiled at 0.1–0.3 px; it uses the same unit-tested `SkeletonStroke` as the preview.
- The window has no drop shadow, because the window CanvasGroup clips its children.
- The minimized status pill keeps its 3.3 styling.

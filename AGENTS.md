# Ervi Hub development rules

Read HANDOFF.md, README.md and the current continuation report before changing behavior. Edit `src/` and rebuild; do not hand-edit generated artifacts. Preserve Scope cleanup, early `_G.RNG_HUB_STOP` registration and Auto Roll's one-request/no-uncertain-retry guarantees. Retain the existing checkout; cloud tasks are isolated, so do not create worktrees unless explicitly requested.

Every new floating HUD, panel or separate window must use `FloatingWindow` or provide an equivalent justified implementation: themed, configurable from the hub menu, draggable where appropriate, corner-resizable, constrained to the visible viewport, and with persistent position and size when file access is available. Use scrolling content to accommodate large fonts. Avoid standalone Close buttons; menu controls own enabling/disabling. Ensure all instances and event connections are disposed when disabled or unloaded. Document any technical exception.

The Safe Zone is the owner-requested fixed destination (278.78, -16.30, 7.82), scoped to PlaceId 119338513416973. The latest user request requires staying there rather than falling: translate once on OFF → ON and hold the local root anchored with falling/spin velocity cleared. Use PositionHold's transactional release and Scope cleanup; restore the pre-existing anchor state on OFF, death, root/character removal, unload and rerun. Never replay old falling velocity. Release if another actor unanchors or displaces the character; do not fight server corrections or run repeated teleports. No automatic move on respawn/reload. Server acceptance remains unverified; do not label local physics as server-approved. The key defaults to NONE. No server-designated protected zone or automatic-M1 API is established. Do not invent remotes or bypass movement/cooldown validation. Keep unsupported requests visibly distinct from executed actions.

Use Desktop Commander for authorized Windows work if exposed; the Linux cloud shell does not access the user's PC. Do not claim deployment or live Roblox validation based on headless tests. Keep Potassium's autoexec directory empty. Preserve repository visibility; publishing/distribution must follow the user's authorization.

Before release, run the unit and smoke suites, compile both generated artifacts, verify deterministic outputs, update current documentation, and preserve rollback history. Historical reports are evidence for their original versions only.

For the 3.0 interface, add persistent settings to FeatureSchema and compose Ui components so controls register for search. Keep Config import data-only and bounded; preserve legacy settings and per-game autoload. Use PropertyOverrides for scoped property ownership/restoration. Visuals: the owner explicitly requested a Through Walls toggle in 3.3 (default on); with it off, occluded targets are suppressed and Highlight.DepthMode stays Occluded. Dead/invisible-headed/filtered targets are always suppressed; honor target/skeleton/update budgets and release all drawing resources. Never add a CFrame speed fallback, collision bypass, wallhack or automated attack to fill an unsupported reference control. EN/RU covers interface labels; diagnostic evidence and player/game data stay verbatim. Update UI_FEATURE_CHECKLIST.md when feature status changes.
